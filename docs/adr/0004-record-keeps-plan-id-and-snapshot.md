# 沖煮記錄存所依計劃的 id，參數另抄一份

（#147）

沖煮記錄可以標明**所依計劃**：`cupping_records` 加上計劃 id 與計劃名稱。存記錄的時候，把計劃當下的參數抄進記錄現有的五欄：方法（濾杯）、研磨度、水溫、粉水比（`1:N`）、萃取時間（總時間）。之後計劃被改或被刪，記錄都不變。粉量和步驟不抄。

- 計劃 id 是一般文字、不設 FK：自己的計劃（DB 的 id）和內建手沖法（`app.js` 裡的字串，例如 `builtin-kasuya-4-6`）放在同一欄。計劃刪了照刪，記錄顯示抄下來的名稱加上「（計劃已刪除）」。
- 這次沒完全照計劃的地方寫在記錄的備註，不在表單上改參數。表單選了計劃之後，沖煮參數卡只顯示一行唯讀摘要。
- 沒有所依計劃的新記錄只記方法；研磨度、水溫、粉水比、萃取時間的 input 拿掉。舊記錄照原樣顯示，不做資料搬移。

記錄要回答兩件事：「照哪個計劃沖的」和「當時的參數是什麼」。只存 id 只能回答前者，只抄參數只能回答後者。

## Considered Options

- **只存計劃 id，畫面上跟著計劃現在的樣子**：不採用。計劃從 93°C 改成 91°C 之後，三週前那杯的評分會對上它沒用過的參數。
- **計劃被用過就不能改，要改只能另存新的**：不採用。計劃清單會越積越多，而且要為「被用過」另外管一套狀態。
- **保留五個可以編輯的 input，計劃只當填表的起點**：不採用（作者）。卡片太佔空間，帶入之後也說不清這筆記錄到底照哪個計劃沖的。
- **計劃刪除用 `ON DELETE RESTRICT`（比照店家）**：不採用。參數已經抄進記錄，計劃不在也不缺東西；而且內建手沖法根本沒有 FK 可以設。
