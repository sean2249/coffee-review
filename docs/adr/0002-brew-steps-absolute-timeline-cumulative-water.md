# 沖煮步驟：單一絕對時間軸、只存累計水量

`brew_plans.steps`（#145）的每個時間都是「從 0:00 起算的秒數」：注水存開始時間 `at_seconds`，等待存「等到第幾秒」`until_seconds`，不存「等幾秒」；注水量只存**累計** `to_g`（注到 X g），不存**本次**。整條時間軸只有一套座標，驗證只要「時間不遞減」「累計嚴格遞增」兩條，改前面某一步不會讓後面漂移，之後的計時器拿每步的秒數就能直接排程；食譜也多半寫累計（Hoffmann「注到 300 g」）。

輸入習慣與儲存分開：② 的編輯頁以「本次」為輸入框、時間軸顯示「等 45 秒」，都是換算，不影響存下來的形狀。總時間就是最後一步的時間，沒有另一個「預計完成」欄位。作者對「等幾秒」是否更順手仍有保留——若日後要改儲存形狀，靠 `schema_version` 做資料轉換，不動表結構。

## Considered Options

- **存本次 / 等幾秒（相對值）**：4:6 寫成「60 g × 5」較直觀，但總水量與每一步的時間都要從頭加總，改一步會連動後面所有步驟。
- **悶蒸拆成「注水 + 等待」兩步**：不採用。悶蒸就是第一注，用第一注上的 `bloom` 標記表示；要等多久由下一步的時間表達，拆開只會讓每個食譜多一個空的等待。
- **另存「預計完成」**：不採用（#146 定案）。收尾時間用最後一個等待步驟表達，同一條時間軸，不必維持兩個數字一致。
